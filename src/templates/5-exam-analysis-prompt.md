# Past Paper Analysis (prompt)

> **How to use:** inside your course project, start a new chat. Attach every past exam, quiz, practice midterm, assignment and review sheet you have (answer keys too, if you have them). Fill in the brackets, paste everything below the line, and send. Save the result as **Exam blueprint** in the project files. The practice-exam prompt and the Anki prompts use it.

---

**Course:** [COURSE CODE, Prof name, term]
**Upcoming exam:** [e.g. Midterm 2, Nov 26, Lectures 9–17, 50 min]
**Format I've been told:** [e.g. 30 MC + 2 short answer / "same as MT1" / unknown]
**What I've attached:** [e.g. MT1 from this term (real), 2023 final (same prof), practice MT2 from the course site, weekly quizzes 1–6]

Analyze these materials to work out **what this exam will test and how**. Use the lecture context doc in project knowledge as the map of what this course actually covered and flagged (🎯/⭐/🔹/🚫).

## 1. Rate every source first
Not all practice material is like the real exam. Some courses hand out practice that's from another prof, another term, a textbook, or a different format. For each attached file, give:

| Source | Type | Tier | Format match | Scope match | Difficulty vs real exam | Use it? |
|---|---|---|---|---|---|---|

- **Tier A:** real past exams/quizzes from this course and prof. **Tier B:** practice made for this course this term. **Tier C:** other terms, other profs, textbook or generic questions.
- **Format match / scope match:** compare question types, length and wording to Tier A, and topics to the context doc. Say how close it is in a few words.
- If a source covers topics this course didn't teach, or uses a different format, say so clearly and **down-weight it**. Don't let it drive the predictions.
- If there's no Tier A material, say the predictions are lower confidence.

## 2. Map every question to a topic
Go through each question in the usable sources. Tag it with the topic and lecture from the context doc, the question type (definition, application/scenario, calculation, diagram, compare, experiment design, essay…), and the marks if shown. Group near-duplicates: the prof re-asking the same idea in new words is a strong signal.

## 3. Key exam topics
A ranked table, weighting Tier A most, then B, then C:

| Rank | Topic | Lectures | Times tested (by tier) | Usual question type | Share of marks | Context doc signal | Confidence |
|---|---|---|---|---|---|---|---|

Then:
- **Top 10 to master**, each with one line on *how* it gets asked.
- **Repeat offenders:** ideas that show up on almost every paper.
- **Taught but never tested yet:** 🎯/⭐ topics from the context doc that the papers don't cover. Say whether they're likely to appear now (e.g. new this term, or flagged in class).
- **Probably skip:** topics only in Tier C material, or marked 🚫.

## 4. How this prof writes questions
- Common wording and traps (e.g. "all of the following EXCEPT", two true-sounding options, units).
- What full marks look like on written answers (from answer keys if attached).
- Difficulty mix and how much is recall vs application.

## 5. Exam blueprint
A short prediction of the upcoming exam: sections, number and type of questions, marks, time, and the topic mix (%), based on the most representative sources. Mark each part **known** (stated by the prof or syllabus) or **inferred**.

Keep it skimmable: tables and bullets, no filler. Cite sources as `MT1-2024 Q7` and lectures as `L6`.
